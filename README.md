# thesis-formatter

> 「页边距 2.54cm？学校要的是 2.5cm 哦。」

论文的规矩有 39 条。字号、行距、缩进、题注编号、参考文献格式、图表对齐……
一条一条对下来，眼睛会花。而答辩就在下周。

于是有了这只小工具。你把 `.docx` 丢给它，它替你逐条核对；你点一下，
它把能改的都改好。

**原稿，它一个字都不会动。**

## 它能做两件事

**检查** —— 按学校规范逐条比对，把不合规的地方列出来。每条都标得明明白白：
这一条它自己能改，那一条得你自己动手。

这一步是只读的。你的文件连一个字节都不会变。

**自动排版** —— 按规范把该改的改好，另存成一份新文件。

它从不覆盖原稿。就算改坏了，你的论文也还好好躺在原地，一页都没少。

> **先说清楚：这是非官方个人项目，和学校没有关系。**
> 规则整理自学校官方模板里的 39 条批注，但模板原件和真实论文样本都不随本仓库分发
> （一个是学校材料，一个含姓名和未发表内容）。要跑回归测试请自备样本，
> 文件不在时相关测试会自动跳过。

## 让它跑起来

**图形界面**（推荐）：

```bash
python -m pip install -r requirements-gui.txt   # 只有界面需要 PySide6
python app.py
```

把 `.docx` 拖进去，点「开始检查」（只读）或者「自动排版并另存…」（可以勾"仅预览"）。

结果分四页：重点问题 / 完整清单（能按分类折叠、能搜、能筛"要不要我动手"）/
改动清单 / 文档概况。

**命令行**：

```bash
# 检查一篇论文
python check_docx.py 论文.docx --rules rules/中南林科大_硕士_学术学位_理工类.yaml --report report.md

# 自动排版（先加 --dry-run 可以只看不改）
python formatter.py 论文.docx --rules rules/xxx.yaml --output 修正后.docx --dry-run
python formatter.py 论文.docx --rules rules/xxx.yaml --output 修正后.docx
```

不想装 Python 也没关系，Releases 里有两个文件：

- **`ThesisFormatter.exe`** —— 双击就能用，最省事
- **`ThesisFormatter-portable.zip`** —— 解压后双击里面的 exe。它不往临时目录写东西，
  也不容易被杀软误报

## 它会替你盯着这些

页边距 · 页面尺寸 · 页码格式 · 脚注编号 · 缺失章节 · 图表题注编号与中英一致性 ·
字号 · 中文字体 · 西文字体 · 行距 · 段前段后 · 缩进 · 对齐 · 标点全角半角 ·
**标题与正文同段** · **异常字符**（不换行空格 / 零宽字符 / 私有区字符 / 同义字符混用） · 字数

报告分「重点问题」和「完整清单」两段。重点区筛的是**人眼看得见**的问题
（全部错误、整体不符规范的类型、章节标题），不是"规则多重要"。

## 自动排版时会动什么

四层，改动面从小到大：

1. **文档级**（`w:sectPr`）——页边距、页面尺寸（横向页跳过）、页眉页脚边距、
   页码格式分段（摘要到目录用大写罗马数字，正文从阿拉伯数字 1 重新开始）。
   封面和声明页不碰。
2. **样式级**（`word/styles.xml`）——把规则写进样式定义（中西文字体、字号、行距、
   缩进、对齐、大纲级别）。**这是改动量最小的一层**：某样本论文的二级标题
   `ascii` 字体是宋体（"1.2" 显示成宋体），27 段全错，改 1 处样式就全好了。
3. **段落级**（`w:pStyle`）——把段落指到对应样式，并清掉会盖住样式的直接格式
   （`spacing`/`ind`/`jc`/`outlineLvl`，以及 run 的 `sz`/`szCs`/`rFonts`）。
   加粗、斜体、上下标这些**有语义的格式一律不动**。
4. **文本级**（`w:t` 里的字）——题注图号后补一个半角空格；异常字符按规则处置
   （NBSP 换半角空格、零宽和私有区字符删除、µ 统一成 μ、替换字符 U+FFFD 只报不删）；
   两侧都是中文的半角标点转全角。

   例外：私有区字符 **U+E5E5 是换成半角空格，不是删掉**——样本里它顶替空格用
   （六个一级标题只有"第一章"那个位置是它，其余五章都是真空格）。

**它有三类东西不碰**（都会写进报告）：

- **含引用域的段落**——实测改了会被 Zotero 刷新覆盖，还会触发它的"引注已被修改"
  提示，对你是纯干扰。不过文本层是**按节点**避让的，域外的普通文字照改
  （引用标注旁边的括号不受影响）。
- **目录条目**——由 TOC 域生成，改了会在刷新目录时被覆盖。报告里标成
  「建议手动修改」，别以为是它漏了。
- **图片独占一段的段落**——段里没有文字可排，套样式只会给图加上首行缩进；
  而且正文样式的固定行距会把嵌入型图片裁掉。
  段里同时有文字和图片的（标题、题注）**照常排版**，只把行距钉成单倍。

跑完一份 103 页的样本论文（四层全开）：

| | 错误 | 警告 | 提示 |
|---|---|---|---|
| 原稿 | 4 | 73 | 11 |
| 修正后 | 3 | 11 | 7 |

剩下的 3 个错误是内容问题（表4.1/4.2 编号与中英题注不符），不是格式问题。

引用域 105 条逐字节不变；除了 `document.xml` 和 `styles.xml`，剩下 69 个 zip 部件
哈希全不变。只开文本层时：29 处题注缺空格、6 个异常字符、13 个半角标点全部处理，
147 条 `w:instrText`（含 105 条 Zotero 引用域）逐字节不变，
run 数 6284、`w:t` 数 5514 也不变，**而且只替换了 `word/document.xml`**。

两条硬约束写在代码里：**只改 `document.xml` 和 `styles.xml`**（其余部件照抄，
所以"没动别的"是可验证的）、**拒绝原地修改**（输出路径和输入相同就直接报错）。

## 它现在还做不到的事

- **只认 `.docx`，不认 `.doc`**（Word 97 二进制格式）。这不是"还没做"，是能力边界：
  python-docx 读不了旧格式，短期也不会支持。拿 `.doc` 进来它会告诉你"可能不是有效的
  `.docx`"，先用 WPS 或 Word 另存为 `.docx` 再跑。
- 分页效果（章末大片空白、图和题注分离）——`.docx` 里没有分页信息，只能看渲染结果
- 公式编号与排版
- 封面各字段
- 分类器依赖章节锚点和编号模式；完全不标大纲级别、也不用标准编号的文档会退化
- 半角方括号 `[]` 不自动转全角：全角方括号有 ［］ 和 【】 两种写法、语义不同，
  机械替换会改错意思，降级成"需人工判断"
- 替换字符 U+FFFD 只报不删（删掉等于把"这里丢了字"的线索也删了）
