# thesis-formatter

中南林业科技大学硕士学位论文格式工具：**检查**（只读）+ **格式化**（文档级 / 样式级 / 文本层）。
正文级的格式（字号、字体、缩进）走样式层，逐段写直接格式未做。

> **非官方个人项目，与学校无关。**
> 规则整理自学校官方模板里的 39 条批注；模板原件与真实论文样本**都不随本仓库分发**
> （前者是学校材料，后者含姓名与未发表内容）。要跑回归测试请自备样本，
> 文件不在时相关测试会自动跳过。

## 现状

| 模块 | 作用 |
|---|---|
| `docmodel.py` | 文档模型层。一次解析 `.docx`，算出每个段落的**有效格式**（run → 样式链 → 文档默认） |
| `classifier.py` | 位置感知分类器。按章节锚点切段，判断每段属于哪种类型 |
| `check_docx.py` | 按 YAML 规则比对，输出 Markdown 报告 |
| `formatter.py` | 格式化入口：页边距 / 页面尺寸 / 页码 / 样式 / 文本 |
| `wordstyles.py` | 样式层：把规则写进 `word/styles.xml` |
| `textfix.py` | 文本层：题注缺空格、异常字符、半角标点。政策函数与检查器共用 |
| `extract_spec.py` | 从模板的 Word 批注里抽规范原文 |
| `pdf_probe.py` | 从 PDF 反向测量排版参数（开发期工具，非产品功能） |
| `field_safety_test.py` | 验证改格式会不会破坏 Zotero 引用域 |
| `app.py` | 图形界面（PySide6）。拖入 docx → 检查 / 格式化 → 看结果 |
| `gui_worker.py` | 界面的后台线程与错误翻译（不 import 控件，可无头测试） |
| `build_exe.py` | 一条命令打包成单文件 exe |
| `exp/` | 对照实验的脚本与产物（判据验证、真机验证文件的生成） |
| `tests/` | 147 条测试 + 变异测试（45 处） |

规则在 `rules/中南林科大_硕士_学术学位_理工类.yaml`，来源是学校模板 `word/comments.xml` 里的 **39 条批注**。

## 图形界面

```bash
python -m pip install -r requirements-gui.txt   # 只有界面需要 PySide6
python app.py
```

拖入 `.docx` → 「开始检查」（只读）或「自动排版并另存…」（可勾"仅预览"）。
结果分四页：重点问题 / 完整清单（按分类折叠 + 搜索 + 按"要不要我动手"筛） /
改动清单 / 文档概况。

**用词说明**：界面上一律说「自动排版」，不说「格式化」——中文里"格式化"首先让人
想到清空磁盘，放在论文工具上会吓到人。代码和本文档里仍叫 `formatter` / "格式化"
（技术名词，指按规范整理格式），两者是一回事。

三条刻意的设计，改代码前先看一眼：

- **没有取消按钮。** `load()` 内部没有中断点，`QThread.terminate()` 会直接杀线程，
  而 `_write` 不是原子写——杀在半路会留下一个残缺的 `.docx`。所以宁可慢，
  运行期间禁用按钮，用进度条和计时器证明还活着。
- **不把 Markdown 报告反向解析回界面。** 界面直接吃 `run_check` 返回的结构化数据，
  报告格式改了界面也不会跟着坏。
- **进度靠 `on_stage` 回调**，不是界面上另写一套流程。`run_check` / `apply`
  各接一个可选的关键字参数，在阶段边界回调一次；核心模块不知道 Qt 存在。

打包：

```bash
python build_exe.py            # 产物在 dist/ThesisFormatter.exe
python build_exe.py --clean    # 先清掉上次的
```

打包时会把规则文件复制成 ASCII 名（`staged_rules/default.yaml`）再塞进 exe——
中文路径进 `--add-data` 是最容易翻车的一环；运行时按扩展名找规则，
代码里不写死那个中文文件名。

实测产物 **49MB**（排掉 QtWebEngine 那一批没用到的模块之后，比预想的小很多），
第一次启动要解压，会等几秒。跑完确认过：归档里带上了 `rules/default.yaml` 和
QtCore/QtWidgets，双击起得来。

```bash
# 检查一篇论文

# 格式化（先 --dry-run 看会改什么）
python formatter.py 论文.docx --rules rules/xxx.yaml --output 修正后.docx --dry-run
python formatter.py 论文.docx --rules rules/xxx.yaml --output 修正后.docx
python extract_spec.py 模板.docx -o spec_raw.json

# 只跑文本层（做真机验证时用：只替换 document.xml，其余部件逐字节照抄）
python exp/make_textonly.py 论文.docx 只改文本层.docx

# 跑测试
python -m pytest tests/

```

## 格式化做了什么

四层，改动面从小到大：

1. **文档级**（`w:sectPr`）：页边距、页面尺寸（横向页跳过）、页眉页脚边距、
   页码格式分段（摘要→目录用大写罗马数字，正文起阿拉伯数字重新从 1）。封面与声明页不改。
2. **样式级**（`word/styles.xml`）：把规则写进样式定义（中/西文字体、字号、行距、
   缩进、对齐、大纲级别）。**这是改动量最小的一层**——某样本论文的二级标题的
   `ascii` 字体是宋体（"1.2" 显示成宋体），27 段全错，改 1 处样式全解决。
3. **段落级**（`w:pStyle`）：按分类结果把段落指到对应样式，并清掉会盖住样式的
   直接格式（`spacing`/`ind`/`jc`/`outlineLvl` 与 run 的 `sz`/`szCs`/`rFonts`）。
   加粗、斜体、上下标等**有语义的格式一律不动**。
4. **文本层**（`w:t` 里的字，见 `textfix.py`）：题注图号后插 1 个半角空格；
   异常字符按规则处置（NBSP→半角空格、零宽/私有区字符删除、µ→μ 统一、
   替换字符 U+FFFD 只报不删）；两侧都是中文的半角标点全角化。
   例外：私有区字符 **U+E5E5 换成半角空格而不是删掉**——样本里它顶替空格用
   （六个一级标题只有"第一章"那个位置是它，其余五章都是真空格）。

**跳过的三类**（都写进报告）：
- **含引用域的段落**——实测格式改动会被 Zotero 刷新覆盖，还会触发它的
  "引注已被修改"提示，对用户是纯干扰。见 `zotero_refresh_test.py`。
  注意：文本层是**按节点**避让的，域外的普通文字照改（引用标注旁边的括号不受影响）。
- **目录条目**——由 TOC 域生成，改了会被覆盖。
- **图片独占一段的段落**——段里没有文字可排，套样式只会给图加上首行缩进；
  而且正文样式的固定行距会把嵌入型图片裁掉（见下面第 13 条）。
  段里同时有文字和图片的（标题、题注）**照常排版**，只把行距钉成单倍。

跑完一份 103 页的样本论文（四层全开）：

| | 错误 | 警告 | 提示 |
|---|---|---|---|
| 原稿 | 4 | 73 | 11 |
| 修正后 | 3 | 11 | 7 |

剩下的 3 个错误是内容问题（表4.1/4.2 编号与中英题注不符），不是格式问题。
提示少了 4 条是因为页码分段归一后，说明性条目合并了。

引用域 105 条逐字节不变；除 `document.xml` 与 `styles.xml` 外 69 个 zip 部件哈希全不变。
只开文本层时（`exp/make_textonly.py`）：29 处题注缺空格、6 个异常字符、13 个半角标点
全部处理，全部 147 条 `w:instrText`（含 105 条 Zotero 引用域）逐字节不变，
run 数 6284、`w:t` 数 5514 均不变，且**只替换 `word/document.xml`**。

两条硬约束写在代码里：**只改 `document.xml` 与 `styles.xml`**（其余部件照抄，
所以"没动别的"可验证）、**拒绝原地修改**（输出路径与输入相同直接抛错）。

## 检查项

页边距 · 页面尺寸 · 页码格式 · 脚注编号 · 缺失章节 · 图表题注编号与中英一致性 ·
字号 · 中文字体 · 西文字体 · 行距 · 段前段后 · 缩进 · 对齐 · 标点全角半角 · **标题与正文同段** · **异常字符**（不换行空格/零宽字符/私有区字符/同义字符混用） · 字数

报告分「重点问题」和「完整清单」两段。优先区筛的是**人眼看得见**的问题
（全部错误 + 整体不符规范的类型 + 章节标题类），不是"规则多重要"。

## 改代码前必须知道的事

这些都是真踩过的坑，对应的测试在 `tests/` 里都有。

**1. 不要用 `python-docx` 的 `doc.paragraphs`。**
它只遍历 body 的直接子级，会静默漏掉内容控件（SDT）和所有表格内的段落——
实测某样本 1623 段里漏掉 930 段（57%），包括整份目录。一律走 `docmodel.load()`。

**2. 单位有两套。** `pgMar` / `pgSz` 用 twips（1440 twips = 2.54cm）；
python-docx 的 `Length` 是 EMU。搞混了页边距会全线误报。

**3. 字体分 `eastAsia`（中文）和 `ascii`/`hAnsi`（西文），必须分别解析、分别回退。**
`"1.2"` 这类编号走西文字体槽，只查中文字体会漏掉「标题数字显示成宋体」这种很扎眼的问题。
另外 `python-docx` 的 `run.font.name` 设的是 **ascii/hAnsi**，设不了 `eastAsia`。

**4. 字体/字号有四个来源，缺一层就算不出来：**
run 级直接格式（按字符数加权取众数，不是取第一个）→ 样式链 → 主题字体（`w:asciiTheme`）→ 文档级默认（`w:docDefaults`）。

**5. 绝不能重组 run。** 合并 run 或 `paragraph.text = ...` 会**静默销毁 Zotero 引用域**
（实测 105 条 → 98 条，不报错）。改 run 的 `rPr`、清 `rPr`、改文档级设置是安全的。

**6. LibreOffice 转 `.doc` 会丢格式，但**批注文字完好**。**
学校模板只用来取批注（规则来源，已验证二进制无损）；格式验证一律用原生 `.docx` 或 PDF。

**7. 文本层只动 `w:t`，绝不碰 `w:instrText`。**
Zotero 把引用数据以 JSON 存在 `w:instrText` 里。实测某样本 44 个可疑字符里 **38 个在 `instrText`**
（一大半是 JSON 里本来就有 NBSP）。按段落文本盲扫删字符，第一个改坏的就是它，而且不报错。
域内的 `w:t`（`fldChar` begin/end 之间、或 `fldSimple` 之内）也不动——那些字会被重新生成。

**8. lxml 元素的 `id()` 不能用，要用元素本身。**
lxml 的元素代理是临时的，同一个节点每次访问都可能是新的 Python 对象，`id()` 会变，
还可能被回收后复用。`protected()` 起初用 `set` 存 `id(node)`，测试里出现
`[False, False, False]`——该保护的没保护上。元素的 `hash`/`==` 是按底层节点算的，才可靠。

**9. 改完首尾出现空格，必须补 `xml:space="preserve"`。**
否则 Word 渲染时把空格吃掉。实测：NBSP 换成半角空格后，`genes (e.g.,` 和 `CoEXPA2)`
会被粘成一个词；跨节点的题注（图号"3"在图名隔壁的 `w:t` 里）也会白改。
只给"我们新造出来"的首尾空格补，原本就有的裸空格保持原样，免得不小心改变别处的渲染。
（另外：`s[:1] in " \t"` 这种写法不能用，空串是任何字符串的子串，`"" in " \t"` 为真。）

**10. `Para.text` 是 `load()` 时的快照，改完字不会自动同步。**
所以"跑两遍看是否幂等"必须**写文件再重新 load**，在同一棵树上连跑两次会重复插入
（`fix_caption_gaps` 会看到旧文本，再加一个空格）。

**11. 界面里的活儿一律在后台线程干，跨线程只走 Signal。**
在 `JobThread.run()` 里碰任何控件都会崩或静默错乱。跑完一次任务后
**不要把同一个 `Doc` / `rows` 交给第二次操作**——lxml 树不是线程安全的，
而且 `run_check` 返回的 doc 已经被改过，再喂给 `apply` 会重复施加文本修复。

**12. 规则文件有"接线"守卫测试**（`tests/test_rules.py`）。
规则里每个叶子键，要么代码里读得到，要么登记在 `not_implemented` 里——
新加一条规则忘了接线，测试会红。它专抓 `new_page`、`gap_after_number` 这类
有特征的名字；像 `align`、`size_pt` 这种通用名，别处也在用，抓不到。
反过来（实现了却忘了从列表里删）只能靠自觉，测试帮不上——原因见该文件里的注释。

**13. 含图片的段落：不能给它固定行距，但也不能整段跳过。**
固定行距（`lineRule="exact"`）会把**嵌入型图片裁掉**——图片坐在行里，行高锁死就超出部分被裁；
环绕型图片浮在文字层之上，不受影响，所以问题只在嵌入型上冒头。
（`atLeast` 不会裁，行可以变高，别一并处理。）

但"只要含图就整段跳过"是**错的**：图片常锚在标题或题注里，跳过会把标题也跳掉
（用户实测"3.3 那个标题没排上"）。现在的规则是：

- **图片独占一段**（段里没字）→ 整段跳过；但它自己带的固定行距要救回单倍。
- **段里有字** → 照常排版；只有"要套的样式给的是固定行距 **且** 段里有嵌入型图片"时，
  才在这一段上写一条直接格式把行距钉成单倍。

检查器那边不拿样式规范去要求图片独占的段落（报了用户也改不了，只是噪声）。
实测：某样本论文完整排版后 31 张内嵌图全被压扁过，而"只改文本层"的验证文件看不出来——
**验证一层就只验到那一层**，别拿一层的干净去推断另一层。

**14. 样式层要显式写加粗，不能"不管"。**
Word 内置的 `heading 2/3/4` 样式**自带 `<w:b/>`**。我们改了字体字号却没管加粗，
结果把标题弄成了粗体——规范要的是"黑体 三号"，从没说加粗（黑体本身已经够重，
再叠一层粗就是双重强调）。规则里写了 `bold` 才去动：`true` 强制加粗、`false` 强制不加粗，
所以标题都标了 `bold: false`（ABSTRACT 标题按规范是 `true`，只此一处）。
另外 `w:rPr` 的子元素**有顺序**（rFonts → b → bCs → sz），`b` 要插在 rFonts 后面，
不能直接 append 到末尾。

## 关于"异常字符"为什么用黑名单

不换行空格（U+00A0，WPS 里显示成 `°`）、零宽字符、私有区字符（U+E5E5 这类 WPS 垃圾）
是 AI 生成文本和跨软件复制的典型痕迹，要报。

但**必须用黑名单**：白名单式地"报一切非常见字符"会淹在制表符、℃、外国人名重音字母
（RÍOS、BLÁZQUEZ）、罗马数字（Ⅲ）、勾选框（□）这些完全正常的用法里。
实测某样本 368 个制表符 vs 4 个真问题——误报率会高到报告没法看。

规则里每个区间还带一个 `fix` 处置，格式化器照此执行：
`space`（换半角空格）/ `delete`（删掉）/ `report`（只报不改，默认）。
写在 YAML 而不是代码里——"哪些该删、哪些只报"是会变的政策，改规则的人应该直接改得到。
比如替换字符 U+FFFD 就用 `report`：它说明原稿这里本来就丢了字，自动删掉等于把线索也删了。

**区间按先后顺序匹配，先命中的生效**，所以特例要写在通用区间之前。
U+E5E5 就是这么处理的：它落在"私有区字符（0xE000–0xF8FF）删掉"这个通用区间里，
但样本里它是在顶替空格（六个一级标题只有"第一章"那个位置是它），
所以为它单列一条 `space` 放在前面。删掉它，第一章就成了唯一没有间隔的标题。

## 尚未覆盖

- 分页效果（章末大片空白、图与题注分离）——`.docx` 里没有分页信息，只能从渲染结果判断
- 公式编号与排版
- 封面各字段
- 分类器依赖章节锚点与编号模式；完全不标大纲级别且不用标准编号的文档会退化
- 半角方括号 `[]` 不自动全角化：全角方括号有 ［］ 与 【】 两种写法、语义不同，
  机械替换会改错意思，只降级为"需人工判断"
- 替换字符 U+FFFD 只报不删（删掉等于把"这里丢了字"的线索也删了）
